# 小安数字健康管理师 EXE 使用说明

## 启动

直接双击：

项目 `release` 目录中的 `XiaoAn-Health-Kiosk-1.4.13-x64.exe`

应用默认使用全屏窗口启动，并优先选择 Windows 已设置为竖向的显示器；应用画布本身保持居中竖屏卡片，左右和上下保留安全区，不再横向填满整个窗口。内容旋转为 0°，不会在 Electron 内翻转画面，按钮也不会被拉伸到屏幕外。按 `F11` 可切换窗口状态，按 `Ctrl + Shift + Q` 可退出。

## 首次连接 DeepSeek

1. 点击“开始说话”。
2. 在管理员首次设置窗口中粘贴新的 DeepSeek API Key。
3. 点击“安全保存并开始对话”。

密钥使用 Electron `safeStorage` 调用 Windows 当前用户加密服务保存到应用数据目录，不写入源码或 EXE。若不配置密钥，可点击“先体验本地对话”，测评与常用健康问答仍可运行。

## 语音

- 打包版内置开源 `sherpa-onnx` 离线语音引擎，不依赖 Windows 语音组件或在线语音服务。
- 中文识别使用 SenseVoice Small INT8；中文播报只保留“小安默认女声”，模型推理均在本机完成。
- 浏览器开发预览仍会使用浏览器 Web Speech 作为兼容回退；桌面版会优先使用内置模型。
- 数字人播报可通过底部“音量”和“慢速”调整。
- 可运行 `pnpm run test:speech` 对一段真实中文 WAV 做识别并实际合成一段语音。

## 真实嘴型

- 对话页的普通健康回答由本机默认女声立即播报，并由同一个 PCM 音频时钟实时驱动本地 Viseme。Ditto GPU 同时尝试生成真实帧流，但 GTX 1660 Ti 当前吞吐低于实时，迟到帧不会覆盖正在同步的本地口型。

## V1.4.13 单嘴平滑与自然眨眼

- 自然眨眼恢复为可见的独立半闭/全闭图层，严格验收同时检查透明度、`display` 与 `visibility`，不再把被 CSS 隐藏的眨眼状态判为通过。
- 时间戳口型以音素轮廓决定主要开度，PCM 音量只做轻微强调，持续元音不会在波形谷值反复闭合。
- 相邻嘴型保持固定、对称的嘴部取样区域，每一帧只绘制一张满不透明摄影嘴型；下颌开度随连续音素轮廓衰减，避免双嘴、右脸抖动和透明叠加模糊。

## V1.4.12 本地音素对齐与连续唇形

- 通过内置 ImageGen 的身份保持编辑，仅清理鼻翼到嘴角两侧的法令纹与硬阴影；保留人物身份、五官、闭嘴形状、机位、光线、服装和背景，并保存为版本化母版 `xiaoa-ditto-master-v1.0.3.png`。
- 9 张 Viseme、4 张表情和 2 张眨眼素材全部从同一新母版重新合成；表情遮罩不再覆盖鼻唇沟与脸颊下部，避免说话时把旧法令纹重新叠回画面。
- 字符时间线保留协同发音预测，但摄影嘴型不再用两层透明度混合；任一时刻只显示一张满不透明嘴型，并在协同发音中点切换，由连续下颌承担中间运动，避免运动中出现双唇纹理和模糊。
- 下颌与下半脸增加受口腔开度约束的连续二维形变；形变遮罩从嘴角以下开始，鼻子和人中保持在刚性主肖像，不随音节上下移动。头部低频微动和呼吸幅度提升到终端距离可感知但不夸张的范围；PCM 能量不会独立驱动脸颊抖动，Viseme、Blink、Expression 仍为彼此独立的图层。
- 口型时间线新增 `vits-native-phoneme-durations` 优先契约；当前 sherpa-onnx Node 绑定未导出 VITS 内部时长时，会明确降级到 SenseVoice 字符时间戳，再降级到 PCM 包络，不伪装成“原生时长”。
- 发布前可用 `pnpm mfa:setup`、`pnpm mfa:align` 和 `pnpm mfa:audit` 对单条中文 WAV 做 MFA 强制对齐，并以覆盖率、中位漂移和 P95 漂移审计运行时口型。MFA 不进入终端运行时。

## V1.4.10 姿态与面部动效

- 上半身改为以腰腹为锚点的低频重心摆动、呼吸上抬和句末轻微点头；说话期间不再主动压低动作幅度，眨眼期间会锁住同一姿态，避免头肩突然跳动。
- 有字符时间戳时，口型直接使用音频时钟已有的 68-112 ms 预协同交叉过渡；只有无时间戳回退路径使用 96-122 ms 过渡。主导帧始终唯一，避免重复延迟、硬切、双嘴和默认嘴角漏出。
- 语义表情改为 640 ms 缓入，声音能量对眉眼强度的影响被限制为极小范围，减少眉毛随逐音节抖动；脸颊仅使用低强度软遮罩补足整体表情。
- 严格验收必须同时覆盖打包 Electron 自然 TTS、连续帧上半身位移、CLOSED/A/E/O/U、自然眨眼、真人同文时序、真实点击打断和 GPU 健康状态。

## V1.4.9 部署与诊断

- V1.4.9 在每个流式 PCM 分块播放前用独立 SenseVoice Worker 取得字符级时间戳，再按实际字符注音生成口型；不再只依赖估算字长或播放线程上的二次延迟。
- Electron 会等到 IPC 声明的全部语音分块送达再撤销监听，避免最后一个分块偶发丢失造成“文字仍在、声音和口型提前结束”。
- 口型协同过渡扩展为 92–160 ms，时间戳驱动路径使用更短的 12 ms 候选确认和 84 ms 最小保持，减少抖动但不把口型再次拖慢。
- 表情不再整段满强度贴图，改为 520 ms 缓入、低幅呼吸/韵律变化和受控峰值，眨眼仍保持独立眼睑层。
- 真人同文验证使用 3 段 CC BY 3.0 普通话视频，分别比较嘴巴开合、宽度、字符顺序和归一化时序；结果见 `qa/reference/v1.4.9-real/summary.json`。

- `--diagnostics-json`：不打开窗口，输出屏幕尺寸、屏幕旋转、内容旋转目标、离线模型和语音服务状态。
- `--soak-test-minutes=30`：打开正常界面并持续采集渲染进程异常、无响应、加载失败和进程内存，完成后写入 `XiaoAnHealthKiosk/soak-latest.json`。只有运行稳定、离线语音就绪且物理屏为 1920 × 1200 才通过全部门槛。
- 离线 SenseVoice 会在说话期间以约 1.8 秒节流、最近 10 秒滚动窗口显示中间识别；最终结果仍使用完整语音重新识别。
- V1.4.2 已针对本机 Realtek 麦克风的低电平远场输入调整自适应语音门限，并要求连续两帧声音才开始录音，降低“听不到”和瞬时碰撞误触的概率。
- V1.4.5 将口腔层提升到静态人物图上方，提高本机 Viseme 的可见度；进入“直接和小安说话”后会先播放欢迎语，再自动开始聆听。
- 闭眼素材拆成左右眼独立叠层，屏幕右眼使用自然闭合的屏幕左眼镜像，避开原素材右眼的灰色残影。
- 本机 TTS 播放增加受控增益补偿，解决模型原始 PCM 电平较低时系统音量 80% 仍听不清的问题。
- 实时 JPEG 帧使用与静态人物和欢迎视频相同的等比裁切，不再因横向舞台拉宽人物。
- 声音准备完成后立即播报；Ditto 帧只有在与音频时间差不超过 180ms 时才接管，过期帧会丢弃，避免嘴型落后声音。
- GTX 1660 Ti 路线默认使用 12 步扩散、1280 最大边长和启动预热；这是画质与延迟的本机平衡档。
- 本地 Viseme 回退在音频时钟上增加句首闭口、元音保持和标点停顿，音量门限按当前音色动态归一化；播报链增加轻量低频清理、语音清晰度补偿和柔和动态压缩。
- DeepSeek SSE 读取器支持增量回复、取消、30 秒超时，并可通过注入模拟流做离线端到端回归。
- `scripts/register-kiosk-autostart.ps1`：按当前 Windows 用户注册或移除开机启动，不需要管理员权限。
- `scripts/kiosk-watchdog.ps1`：主进程异常退出时限频重启；正常退出不会重启。
- 运行指标保存在当前用户应用数据目录的 `XiaoAnHealthKiosk/telemetry/runtime-metrics.jsonl`，只记录阶段、耗时和成功状态，不记录健康问题、识别文本或回答正文。
- 动态回答使用真实 Ditto 帧流：本机 `/v1/render/frames` 在推理过程中以 multipart JPEG 逐帧返回，Electron 解析后转发给 Canvas。声音准备好后立即播放，本地 Viseme 从首字开始驱动；GTX 1660 Ti 生成的 Ditto 帧只有在未落后音频超过 180ms 时才接管，过期帧直接丢弃，不会退回整段 MP4。
- 本机健康接口必须报告 `frameStreaming: true`、`renderMode: multipart-jpeg-frames` 和 `provider: Ditto TensorRT/PyTorch Hybrid CUDA`。若接口未启动或连接到旧版 MP4 服务，应用会明确降级到本地 TTS 与 Viseme，不会把完整 MP4 称为帧流。
- DeepSeek 流式回答按完整语句依次提交 Ditto 帧流，每句可打断；新一轮输入会取消当前音频和本机帧请求。
- 首次部署运行 `pnpm run ditto:setup-local`：安装本机推理依赖并下载约 2.31GB 的官方 Ditto PyTorch 最小权重集。GTX 1660 Ti 属于 Turing 架构，不能使用项目原先的 `ditto_trt_Ampere_Plus` 引擎。
- 每次使用前运行 `pnpm run ditto:local`，服务只监听 `http://127.0.0.1:8788`，不暴露到局域网或公网。启动脚本会检查 CUDA、模型、配置和人物图，并为 6GB 显存设置较小的 PyTorch 分配块。
- 可访问 `http://127.0.0.1:8788/health` 查看模型、GPU、忙碌状态及缺失文件；访问 `/v1/capabilities` 查看帧流能力。
- 2026-08-28 本机实测：12/12 个 Ditto PyTorch 文件完整，共 2,314,719,638 bytes；健康接口返回 `provider: Ditto PyTorch CUDA`、`frameStreaming: true`、`renderMode: multipart-jpeg-frames`，GPU 为 NVIDIA GeForce GTX 1660 Ti 6GB。7.01 秒真实 WAV 收到 176/176 张有效 JPEG，热启动首帧 5.198 秒，完整生成 160.56 秒，生成速率约 1.13 FPS；随后由 Electron 按 25 FPS 同步播放。取消测试在第 10 帧中断成功，服务恢复为非忙碌状态。该显卡可稳定本地生成，但不属于实时生成性能。
- GTX 1660 Ti 上 Ditto 解码器必须使用 FP32；FP16 会产生 NaN 并形成黑色人物区域。当前版本已固定为 FP32，并用首帧及后续关键帧做了肉眼检查。
- Electron 成品展示也已单独验收：打包版内置 TTS 对“您好”生成 7,168 个 16 kHz 音频采样，经正式 `kioskBridge.streamAvatar` 收到 12 帧并在 940×1672 Canvas 中以 25 FPS 播放；播放阶段截图保存为 `ditto-validation/electron-frame-display.png`，可见 1200×1920 正向竖屏界面与正常人物画面。
- 页面显示“正在连接实时嘴型”时表示正在等待本机 GPU 首批画面。首帧时间和实际持续帧率必须在本机服务启动后用真实语音记录，不能沿用旧 MP4 的整段生成耗时。
- 本机 GPU 服务不可用、超时或帧播放失败时，应用会自动切回本机离线语音和音频驱动口型，不阻断健康对话与测评。

## 大屏建议

- Windows 显示方向：纵向。
- 推荐分辨率：1200 × 1920。
- 推荐缩放：100%。
- 确认默认麦克风和扬声器已正确连接。

## 隐私与业务边界

- 健康对话用于健康管理和信息引导，不用于疾病诊断或治疗。
- 结果仅分为“日常管理”和“重点关注”。
- 应用不会展示模型内部推理过程。
- 公共设备投入使用前，应配置独立的 DeepSeek 项目密钥并设置额度上限。
