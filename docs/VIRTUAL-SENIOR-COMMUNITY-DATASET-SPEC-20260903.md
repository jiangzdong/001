# 虚拟长者社区级全量测试集规范

状态：需求已由用户确认，架构规格已建立；数据生成器、16 Tool 数据仓库和全量运行尚未实现或验收。

## 1. 目标与不可妥协边界

- 全量测试集必须覆盖当前正式基线的 5 个 MCP、16 个 Tool，不能以通用 `{ok:true}` 代替接口数据。
- 默认全量档至少包含 10,000 名纯合成长者，形成一个社区量级的横向人群覆盖和纵向历史数据。
- 同一 `seniorId` 在身份、权限、健康、会员和服务记录间必须引用一致；禁止各 Tool 独立随机造成年龄、授权、余额、健康状态互相矛盾。
- 所有数据均为 `synthetic-test-only`，不得从生产库复制、脱敏改写或反推真实居民信息。
- 固定 `datasetVersion + generatorVersion + seed` 必须生成相同主键、字段、关联关系和记录哈希；升级数据集必须新建版本，不覆盖已用于比较的批次。
- 固定 manifest 和硬 oracle 决定 PASS；LLM 只允许生成表达变体和对抗轮次，不得生成权限结果、Tool 事实或最终硬判定。

## 2. 数据规模档位

| 档位 | 合成长者 | 目标用途 | 执行约束 |
|---|---:|---|---|
| `smoke` | 64 | 提交前快速验证 16 Tool 合同、权限和主要异常 | 全确定性，不调用媒体链路 |
| `regression` | 1,000 | 日常回归、失败聚类、趋势对比 | 固定种子；可并发、可断点恢复 |
| `community-full` | 10,000 | 社区级全量数据与全接口回归 | 默认全量档；夜间或人工触发 |
| `stress` | 50,000 | 分页、吞吐、内存、长稳和恢复压力 | 不作为日常必跑；独立性能报告 |

`community-full` 的初始数据预算：

| 数据域 | 最低规模 | 纵向深度 |
|---|---:|---|
| 长者主档与测试画像 | 10,000 | 每人 1 个当前版本，保留画像版本 |
| 身份、同意和匹配状态 | 10,000 人，至少 20,000 次采集/授权事件 | 有效、过期、撤回、未匹配、多人、质量不足 |
| 健康标签 | 80,000 条 | 每人 0–16 条，含正常、异常、冲突和过期 |
| 指标证据 | 1,200,000 条 | 近 1 天、7 天、1 月、3 月、半年五个时间窗 |
| 健康测评 | 40,000 条 | 每人 0–12 次，含无记录、缺失、过期和完整记录 |
| 风险研判历史/保存结果 | 30,000 条 | 支持趋势、证据引用、写入、重试和幂等冲突 |
| 会员账户与等级 | 10,000 份 | 非会员、各等级、有效、临期、过期 |
| 积分流水 | 500,000 条 | 增加、扣减、冲正、过期、零余额和大额边界 |
| 充值记录 | 120,000 条 | 空记录、单页、多页、日期边界、不同业务状态 |
| 消费记录 | 1,500,000 条 | 多类别、多页、退款/撤销、脱敏展示 |
| 站点服务 | 48 项 | 启用、暂停、下线、需预约、资格限制、时间/地点缺失 |
| 站点活动 | 1,500 场/年 | 时区、跨日、取消、满额、报名中、已结束和分页 |
| 公共知识 | 1,200 条 | 已发布、过期、更新、无结果、分类和相关性边界 |

以上约为 350 万级业务记录，不包含运行 trace、批次报告和媒体文件。实际数量由 manifest 固化并在生成报告中给出精确值，不能根据预算值宣称已生成。

## 3. 横向画像维度

10,000 名居民不是 10,000 个随意故事，而是从受控维度生成并保证覆盖：

- 年龄：60–69、70–79、80–89、90+。
- 沟通：慢/中/快语速，短句、重复确认、省略主语、改口、方言化表达、跨轮指代。
- 可访问性：听力、视力、大字偏好、数字熟练度、触控误操作倾向。
- 身份与权限：匿名、待认证、已认证本人、授权过期、权限不足、跨主体拒绝。
- 健康数据：无记录、正常、单项异常、多项异常、数据冲突、数据陈旧、证据不足。
- 会员资产：非会员、零积分、正常余额、高流水、空记录、多页记录、等级临期。
- 使用行为：单轮、澄清、多轮改口、取消、超时后重试、重复提交和恢复。
- 数据质量：完整、部分缺失、字段为空、陈旧、非法枚举、跨机构主键和孤儿引用。

维度分布只用于测试覆盖，不宣称代表真实人口统计。每个关键交叉组合必须有最小样本数，不能只按随机概率碰运气。

每个 Tool 至少覆盖 12 个合同状态：成功、空结果、部分缺失、陈旧、非法输入、未知 ID、跨机构、未授权、拒绝、超时、服务错误、响应合同损坏。列表 Tool 还必须覆盖首页、末页、空页、重复游标和非法游标；写 Tool 还必须覆盖幂等重放与并发冲突。

## 5. 生成与存储架构

1. `community-manifest.json` 固化数据版本、生成器版本、seed、人数、时间基准、各实体精确计数和文件哈希。
2. 人群维度由确定性组合器生成；先满足强制覆盖格，再用带 seed 的 PRNG 填充剩余人口。
3. 领域数据从同一居民主档派生，所有外键通过一致性检查；LLM 不参与数值、权限或业务事实生成。
4. 大表以分片 NDJSON 和只读索引交付，避免新增原生 SQLite 依赖影响 Electron Windows 打包；Fixture MCP 按 ID、日期和游标查询，不能一次把全量载入渲染进程。
5. `smoke` 和 `regression` 可从同一 `community-full` manifest 确定性抽取；不得另造一套无法对比的数据。
6. 通过 Schema、引用完整性、分布覆盖、聚合守恒、金额精度、时间顺序和哈希复验后，数据版本才可冻结。

## 6. 执行层级与成本控制

- 数据完整性层：对 10,000 人和全部记录做全量 Schema、外键、时间、权限和聚合检查，不调用 LLM。
- Tool 合同层：对 16/16 Tool 执行全状态矩阵与 10,000 人可调用性扫描；覆盖分页、错误、超时和幂等。
- Harness 场景层：固定硬场景覆盖全 Tool；日常跑 1,000 人，社区全量档支持断点、并发上限、失败重跑和取消恢复。
- LLM 探索层：只对分层样本生成语言变体；保存后按 artifact 重放。模型成本不应阻止全量确定性测试。
- ASR/TTS/Viseme/V34 媒体层：按年龄、语速、听说特征和失败簇分层抽样；媒体抽样通过不能替代 10,000 人数据完整性与 Tool 合同通过。

## 7. 批量结果与优化统计

报告必须分开显示并导出：

- 数据覆盖：居民覆盖率、实体/字段覆盖率、16 Tool 覆盖率、合同状态覆盖率、权限矩阵覆盖率、时间窗和分页覆盖率。
- 产品质量：总通过率、按 MCP/Tool/场景/画像维度的通过率、P50/P95/最大耗时、错误码、失败断言和失败聚类。
- 探索价值：生成拒绝率、有效变体率、新失败簇发现率、重复失败去重率、晋升为固定案例的数量。
- 趋势：同一 datasetVersion/suiteVersion 的前后差异；数据版本变化时必须标注不可直接横比或提供同版本复跑。
- 可操作建议：按受影响居民数、严重度、可复现性和修复成本排序，能下钻到固定 run、persona、Tool、seed 和 artifact hash。

## 8. UI 对设计方向 1 的修订

- 不再把 3 张画像卡当作数据主体；首屏改为“数据集版本、10,000 人、16/16 Tool、记录量、覆盖率”的社区数据摘要。
- “选择画像”改为“测试人群”，以全量社区、固定基准、分层样本、自定义条件四种入口组织。
- 提供年龄、语速、听视力、数字熟练度、身份权限、健康数据、会员状态和数据质量筛选；显示命中人数与预计案例数。
- 场景区按 5 个 MCP 展开到 16 个 Tool，并显示每个 Tool 的成功/异常/权限/分页状态覆盖，而不是仅列 10 条固定场景。
- 批量动作明确区分冒烟、日常回归、社区全量和压力测试；全量运行前展示预计案例、耗时、并发、可取消和断点恢复信息。
- 统计分析默认展示接口覆盖缺口、影响人数最大的失败簇和同版本趋势，固定基准与探索生成结果不得混算。

## 9. 完成门禁

- 生成报告证明 `community-full` 精确人数不少于 10,000，所有记录均通过 Schema 与引用一致性检查。
- 16/16 Tool 均有真实结构化成功数据及异常状态，Fixture 中不存在通用 `{ok:true}` 成功回退。
- 每个 Tool 的必填输出字段、状态、权限和分页/幂等边界均有自动测试证据。
- 同 seed 两次生成的 manifest 与分片哈希完全一致；不同 seed 保持约束覆盖且主键空间隔离。
- 批量运行可暂停/取消、断点恢复、失败重跑和导出；应用重启后可恢复历史。
- 10,000 人数据与运行结果不得打入正式产品包或写入生产 MCP；UI 持续标明“纯合成测试数据”。
- 完整 Node 回归、数据生成基准、Fixture MCP 契约、目标 UI、Windows 目标机和必要媒体分层抽样分别验收；任一未完成不得宣称全量测试集已经交付。
