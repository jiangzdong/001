# 简短方案与结构化协议

面向用户只显示必要内容；程序可以使用结构化字段控制状态和多输入交互。

## 用户可见文本

### 提问状态

最多两句话：一句确认理解，一句提出当前问题。随后显示二至四个选项和语音入口。

### 结果状态

1. **本次结论**：一句话说明当前最需要关注的事项和不确定性。
2. **现在可以做**：最多三项，具体到动作、时机或频率。
3. **请记录**：只列会帮助观察趋势或就医的信息。
4. **何时就医**：明确立即、尽快或持续后常规就诊的触发条件。
5. **未确认**：只在信息缺失会影响判断时显示。

不默认展示长篇基本信息、完整知识科普、全部对话复述或大量来源。

## 通用结构化协议

```json
{
  "type": "question | result | safety",
  "intent": "symptom | domain | general_assessment | report | medication | mental_health | non_health",
  "route": "当前主路径",
  "status": "collecting | complete | stopped",
  "message": "面向用户的简短中文",
  "question": {
    "id": "稳定的问题标识",
    "text": "本轮唯一主要问题",
    "options": [
      { "id": "稳定选项标识", "label": "可点击也可说出的文字" }
    ],
    "allow_voice": true,
    "allow_skip": true
  },
  "progress": { "asked": 2, "maximum": 5 },
  "safety_action": "immediate | prompt | routine | observe",
  "confirmed_facts": {},
  "missing_facts": [],
  "result": {
    "summary": "",
    "actions": [],
    "monitoring": [],
    "medical_guidance": []
  }
}
```

## 校验规则

- `type=question` 时必须有一个问题、二至四个选项并允许语音；结果字段可为空。
- `type=result` 时不得继续提问；行动不超过三项。
- `type=safety` 时不得附带普通运动、按摩或饮食方案。
- 选项标识必须来自经过审核的问题库；模型可以理解同义表达和缩短措辞，不得临时发明医学分值或危险阈值。
- 无效字段、未知选项、超出轮次或互相冲突的状态由程序拒绝，并使用本地保守流程兜底。

## 推荐会话状态

至少保存：当前路径、主要问题、已确认事实、未确认事实、已问问题标识、关键问题数、澄清数、安全行动、下一步动作。状态属于程序控制，不依赖模型记住整段聊天。
