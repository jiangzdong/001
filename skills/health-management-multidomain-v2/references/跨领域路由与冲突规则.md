# 跨领域路由与冲突规则

用于多个领域同时相关时确定主模块、复用信息和解决建议冲突。

## 主模块选择

- 以用户本次最想解决的结果作为主模块。
- 只把会改变安全性、可执行性或阶段目标的其他领域设为协同模块。
- 一次交互最多突出一个主计划；其他模块以补充提醒或后续步骤呈现。

## 典型协同

- 血糖管理 + 运动康复：运动安排必须考虑用药、进餐、血糖记录和低血糖风险。
- 康复管理 + 运动康复：康复管理负责目标、医嘱、日常生活能力和复盘；运动康复负责动作、剂量、进阶和停止规则。
- 睡眠健康 + 脑健康：先排查睡眠、药物、听力和情绪等可能影响认知表现的因素，不把一次状态不佳解释成认知疾病。
- 按摩健康指导 + 康复管理：按摩只作为舒适或放松支持，不改变术后限制和康复处方。
- 健康评测 + 任一模块：评测汇总公共画像和优先级，不重复生成另一个领域的完整方案。

## 冲突优先级

按以下顺序处理冲突：

1. 危险信号与明确安全禁忌。
2. 医生医嘱、康复处方和设备使用要求。
3. 已确诊疾病、用药事实与身体限制。
4. 用户当前功能和执行环境。
5. 用户目标、偏好和可接受程度。
6. 一般健康建议。

低优先级建议不能覆盖高优先级限制。无法判断冲突时，暂停存在风险的部分，保留可安全执行的部分，并说明需要核实的信息。

## 内部路由表达

- 不向用户展示“调用模块”“路由状态”等内部术语。
- 可以自然说明：“这件事同时和血糖、运动有关，我会把两方面合在一份计划里。”
- 不提供人工转接、寻找工作人员或联系工作人员选项。
